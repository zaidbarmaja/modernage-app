1. نظرة عامة على المشروع

«عصري حداثة» تطبيق موبايل لإدارة أعمال شركة تصميم وتنفيذ، يجمع ثلاثة أنظمة في منصة واحدة: نظام محاسبي، ونظام تسجيل دخول وصلاحيات، ونظام إدارة مهام. الهدف ربط دورة العمل بالكامل — من إنشاء المشروع لدى الإدارة، مروراً بعمل موظفي التصميم والتنفيذ، وصولاً إلى متابعة الزبون لمشروعه لحظياً.

تتحكم الإدارة (Admin) بكل شيء عبر لوحة تحكم حصرية: تضيف الزبائن والمشاريع، وتوزّع العمل بين قسمي التصميم والتنفيذ، وتتابع التقارير اليومية وسجلات الحضور والوصولات المالية. ويرى الزبون كل ما يخص مشروعه في بوابة خاصة به.

نقطة الانطلاق: نبدأ بوحدة واحدة فقط — المصادقة + لوحة تحكم الأدمن (المرحلة 1) — ثم نبني بقية الوحدات تباعاً كما هو موضّح في خارطة الطريق.

2. الأنظمة الأساسية الثلاثة

أ) نظام تسجيل الدخول والصلاحيات

  • تسجيل دخول لكل دور (أدمن / مصمم / موظف تنفيذ / زبون) مع توجيه تلقائي للواجهة المناسبة.
  • إنشاء حسابات الموظفين من قبل الأدمن حصراً (لا يوجد تسجيل ذاتي).
  • دخول موظف التنفيذ مقيّد بالموقع الجغرافي (داخل موقع العمل فقط).

ب) نظام إدارة المهام

  • المشروع نوعان: تصميم أو تنفيذ، ولكل نوع مسار وشاشات خاصة.
  • موظف التصميم يضيف مهامه بنفسه مع تقدير الأيام، ويحدّد «العرض الموالي للزبون».
  • نظام بصمة (حضور/انصراف) وتقارير يومية لكل موظف.

ج) النظام المحاسبي

  • موظف التنفيذ يُصدر «وصل إلكتروني» عند دفع أي مبلغ.
  • الوصل يُخزَّن في قاعدة البيانات ويظهر فوراً في صفحة الزبون وفي لوحة التحكم.
  • ملخص مالي لكل مشروع/زبون داخل لوحة التحكم.

3. الأدوار والصلاحيات

الدورطريقة الدخولالصلاحيات الرئيسية
المدير (Admin) حساب يُنشأ مسبقاً لوحة التحكم الحصرية: إضافة الزبائن والمشاريع، إنشاء حسابات الموظفين، تحديد نوع المشروع وموقعه، ومتابعة كل التقارير والحضور والوصولات.
موظف التصميم اسم مستخدم/كلمة مرور يصدرها الأدمن عرض مهامه، إضافة مهام وملاحظات وتقدير أيام، تحديد العرض الموالي، البصمة، والتقرير اليومي.
موظف التنفيذ دخول مقيّد بالموقع (Geofence) عرض مشاريعه، إصدار وصل إلكتروني، البصمة، والتقرير اليومي.
الزبون رقم الهاتف (رمز/OTP) عرض تفاصيل مشروعه: التقدم، المهام، العرض الموالي، الوصولات والمدفوعات، والتقارير ذات الصلة. (قراءة فقط)

7. المتطلبات غير الوظيفية

  • اللغة والاتجاه: واجهة عربية بالكامل بدعم RTL.
  • المنصات: Android أولاً (اختبار على هاتف فعلي)، مع بنية تسمح بـ iOS لاحقاً.
  • الأمان: قواعد Firestore/Storage تمنع كل دور من بيانات غيره؛ الزبون قراءة فقط.
  • الموثوقية: رسائل خطأ واضحة، وتأكيد العمليات الحساسة (حذف/دفع).
  • الأداء: تحميل سريع للقوائم وتحديث لحظي عند تغيّر البيانات.

8. توجيهات الفريق ومعايير الإنجاز

تعريف «الإنجاز» (Definition of Done)

  • المهمة تعمل وفق «معايير القبول» المذكورة، ومختبَرة على هاتف فعلي.
  • الكود نظيف ومنظّم، وأسماء واضحة، وبدون تكرار غير ضروري.
  • الواجهة عربية وRTL وتتبع الثيم الموحّد.
  • تمت مراجعة الكود (Code Review) قبل الدمج.

تنظيم العمل

  • ابدأ بالمرحلة 1 (المصادقة + لوحة التحكم) قبل أي شيء آخر — هي أساس بقية الوحدات.
  • أنجز المهام بترتيب التبعيات: لا تبدأ مهمة قبل اكتمال ما تعتمد عليه.
  • استخدم Git مع فرع لكل مهمة (branch per task) باسم المعرّف، مثال: feature/T-1.7-create-project.
  • أبلغ فوراً عن أي غموض في المتطلبات بدل الافتراض.
